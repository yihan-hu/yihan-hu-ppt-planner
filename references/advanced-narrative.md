## 1. When to use

Use this guide only for:

- multi-study thesis defenses;
- multi-paper seminars;
- complex sequential analyses;
- replication/conflict/investigation stories;
- presentations where repeated navigation materially helps the audience.

Do not impose these mechanisms on a straightforward single-study talk.

## 2. Study-first rule

For multi-study work, first understand each study independently:

`Study understanding -> Result prioritization -> Scientific claims`

Only then build:

`Cross-study orchestration -> Thesis-level synthesis`

Do not use the thesis-level story to distort which results are scientifically primary within each study.

## 3. Question hierarchy

Build levels when useful:

- thesis-level question;
- thematic/block question;
- study-level question;
- analysis-level question;
- current slide question.

Track whether major questions are:

- pending;
- active;
- resolved;
- resolved with uncertainty.

Every important explicit question should eventually be closed by evidence or explicitly remain unresolved.

## 4. Dependency-driven sequencing

Allow dynamic chains such as:

`Question -> prerequisite -> method -> evidence -> preliminary answer -> new concern -> added background/method -> new analysis -> refined answer`

Use reasoning dependency rather than manuscript section order.

A later analysis may be motivated by a limitation or alternative explanation exposed by an earlier result.

## 5. Tension-resolution sequencing

For replication, conflict, or triangulation stories, explicitly test whether the evidence supports a sequence such as:

`Published or earlier signal -> primary analysis -> apparent contradiction -> diagnostic/decomposition analysis -> reconciled interpretation`

or:

`Replication -> decomposition -> reconciliation`

Do not label disagreement as contradiction until checking whether the analyses estimate the same quantity. Differences in population, time zero, comparator, treatment state, outcome, or estimand may be the scientific point.

When a later analysis explains an earlier result, allow the earlier result to stand on its own long enough for the audience to understand the tension. Conversely, do not stretch routine robustness into separate narrative beats.

## 6. Persistent maps and narrative state

Repeated diagrams are not automatically redundant.

A study map, analysis map, or research-question map can act as a persistent cognitive anchor. Reuse it while changing the highlighted state.

Useful states include:

- pending;
- active;
- resolved.

A later version of the same map may write back previously resolved answers while activating the next analysis.

When planning, record when useful:

- `reuse_frame`;
- `focus`;
- `state_update`.

## 7. Opening and resolved maps

For long talks, consider using the same conceptual framework at the beginning and end.

Opening map:

`What are we going to answer?`

Resolved map:

`What do we now know?`

This is especially effective when multiple studies contribute to a common scientific question.

## 8. Defense backup layer

For each major claim, ask:

`What would a skeptical expert ask next?`

Possible backup topics include:

- participant characteristics;
- full model specification;
- assumptions;
- sensitivity analyses;
- alternate definitions;
- subgroup detail;
- bias discussion;
- additional literature;
- mechanism;
- full figures/tables.

Do not let backup grow without limit. Prioritize high-probability, high-value, or high-risk questions.

## 9. Advanced narrative audit

Check:

- Has each study been understood correctly before synthesis?
- Does the thesis-level framing preserve study-level scientific priorities?
- Do repeated maps genuinely improve orientation?
- Are pending/active/resolved states clear?
- Does every major question close or remain explicitly unresolved?
- Is new background introduced when it first becomes necessary?
- Is the final synthesis more than a list of papers?
- Are backup slides connected to foreseeable challenges rather than leftover content?
